# 方案评估：Claude Code TUI 交互的安全对接与前端适配

> 状态：**已交付 P1/P2**（commit `0a0c4da`，本地未 push）；P0 Gate 已通过；阶段二暂不立项，仅保留方案。已知边界：默认 auto 权限模式不触发权限通知，需 default/manual 模式。

## 一、 背景与目标
我们在之前的评估中确认，不能依靠正则去捕获终端（TUI）输出并自动按键（极易误判，引发灾难）。
为了既保留 100% 原生的 CLI 交互能力，又能让用户在【对话】界面获得更好的体验（不用频繁切屏），我们需要寻找一种**基于官方底层机制**的安全对接方式。

## 二、 核心结论：放弃“解析 TUI”，转向“监听 Hook”
直接通过代码去“操控”或“解析” Claude Code 的 TUI 界面是不可靠的（因为它是重绘的 ANSI 控制符，且绕过标准 PTY 输入）。
**正确路径：利用 Claude Code 官方提供的 Hook（钩子）机制进行结构化的事件响应。**

## 三、 可用的核心 Hook 机制
Claude Code 提供了完善的 Hook 系统，可以完美解决我们的需求：

1. **`Notification` Hook**
   - **触发时机**：当 Agent 处于等待状态（例如等待权限确认或用户输入），且持续约 6 秒未响应时触发。
   - **用途**：安全地通知外部系统。当触发 `permission_prompt` 时，通过中控向后端 SSE 推送一个事件。
2. **`PermissionRequest` Hook**
   - **触发时机**：当工具调用需要用户权限，即将弹出 TUI 确认框时触发。
   - **用途**：结构化拦截。脚本可以返回 `allow`（直接放行）、`deny`（拒绝）或 `ask`（继续走 TUI 弹窗）。

## 四、 推荐的分阶段落地路径（请 doc 评估并派单给 dev）

### 📍 阶段一：安全通知机制（零风险，优先实现）
*   **目标**：在【对话】界面提示用户“底层正在等待确认”，引导用户切回终端操作。
*   **实现方式**：
    1.  在项目的 `.claude/settings.json` 中配置 `Notification` Hook。
    2.  监听 `permission_prompt` 事件。
    3.  触发时，由中控推送给前端。前端在【对话】页面顶部弹出一个醒目的警告横幅：“⚠️ Agent 正在等待权限确认，请点击上方【原生终端】进行操作。”
*   **优势**：完全安全，不改变任何默认交互，极大减少用户不知道 AI 为什么卡住的焦虑。

### 📍 阶段二：结构化确认与自动放行（进阶探索）
*   **目标**：针对部分高频、极其安全的操作（如读取文件、执行已知的安全命令），在对话界面直接提供【同意】按钮，甚至自动放行。
*   **实现方式**：
    1.  利用 `PermissionRequest` Hook。
    2.  开发一个简单的拦截脚本（挂载在该 Hook 上），判断当前请求的命令是否在“白名单”内。
    3.  如果是，直接返回 `allow` 跳过 TUI；如果需要用户确认，则通过前端弹出按钮，用户点击后，由中控的 Hook 脚本返回对应的结果。
*   **风险与边界**：必须从最窄的场景（如仅限 `Read` 工具）开始尝试，绝不能对高危命令（如 `rm`、`git push`）自动放行。
