## 1. 它是什么

让 doc / dev 两个开发窗口通过**自建编排服务**互相派单，而不是依赖 Claude 原生 `SendMessage`：

- 角色注册为独立 OS 进程（`role → pid/pgid/job`）；
- 任务持久化到 SQLite，消息只发指针；
- ACK / COMPLETED 显式确认，没有 ACK 不算送达；
- 每个任务起一个全新 `claude -p` worker（模型 A：任务即进程），Windows Job Object 成组回收；
- 只监听 `127.0.0.1`，Bearer token；不自动 push、不绕过用户权限。

## 2. 架构

```text
┌─────────────┐   MCP(stdio)   ┌──────────────────────┐
│ Claude 会话  │ ─────────────> │ MCP server（每会话一个）│
│ doc / dev   │                └──────────┬───────────┘
└─────────────┘                           │ HTTP 127.0.0.1 + token
                               ┌──────────▼───────────┐
                               │ daemon（常驻）        │
                               │ Registry / Router     │
                               │ Launcher / Monitor    │
                               │ Ledger + SQLite       │
                               └──────────┬───────────┘
                                          │ 每个任务启动一个进程
                               ┌──────────▼───────────┐
                               │ claude -p worker      │
                               │ ack → 执行 → completed│
                               └───────────────────────┘
```

| 组件 | 职责 | 位置 |
|---|---|---|
| daemon | 唯一持有注册表/任务表/消息表；唯一能启动 worker；HTTP 服务 | `tools/orchestrator/service.py` |
| MCP server | 每个 Claude 会话由 `.mcp.json` 拉起一个 stdio 进程，代理到 daemon | `tools/orchestrator/mcp_server.py` |
| CLI | dev 与人工调试：`daemon/register/resolve/need/ack/completed/status/tasks/usage/observability` | `tools/orchestrator/cli.py` |
| worker | 模型 A「任务即进程」：`claude -p` + 角色提示 + pointer + acceptance | `launcher.py` / `router.py` |
| 持久化 | `.claude/orchestrator/registry.sqlite3`（agents/tasks/messages/steps/effects/usage） | gitignored |

## 3. 启动 daemon

daemon 必须由**外部终端**常驻，或由双击脚本以 detached 方式拉起。**不要在 agent 的 Bash 里长期启动 daemon**，它会被 agent 的进程树回收。

### 3.1 双击启动（前台中控）

双击 `scripts\start_orchestrator.cmd`（或直接无参数运行）：

- 无参数 = `-Action foreground -Watch`：先打印「正在启动编排中控...」，随后显示中控横幅与 agent 表；注册/停止等状态变化时重绘，空闲不输出（`7a484ed`）；
- 显式 `-Action foreground`（不带 `-Watch`）只打印启动快照，适合“看一眼就走”；
- Ctrl+C / 异常退出后打印「编排中控已停止」，窗口保留，按任意键关闭；
- 脚本固定加 `-ExecutionPolicy Bypass`，实际逻辑仍在 `start_orchestrator.ps1`；
- 需要后台常驻（不显示面板）时用显式 `-Action start`。

### 3.2 PowerShell

```powershell
# 后台启动（health 通过后返回）
.\scripts\start_orchestrator.ps1 -Action start

# 前台常驻（推荐调试；Ctrl+C 停止并回收 worker）
.\scripts\start_orchestrator.ps1 -Action foreground

# 查看 / 停止
.\scripts\start_orchestrator.ps1 -Action status
.\scripts\start_orchestrator.ps1 -Action stop
```

### 3.3 cmd.exe 入口

```bat
scripts\start_orchestrator.cmd                    # 无参数：前台中控 + 事件驱动刷新（双击）
scripts\start_orchestrator.cmd -Action foreground # 显式写法：只打印启动快照
scripts\start_orchestrator.cmd -Action start      # 后台常驻（detached，不显示面板）
scripts\start_orchestrator.cmd -Action status
scripts\start_orchestrator.cmd -Action stop
```

`.cmd` 带参数时原样转发给 `start_orchestrator.ps1`；无参数时等价于双击进入前台中控并默认 `-Watch`。

### 3.4 等价手工命令

```bash
uv run python -m tools.orchestrator.service --serve --port 0
```

脚本参数（默认值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Action` | `foreground` | `foreground` / `start` / `stop` / `status` |
| `-Port` | `0` | 0 = 随机空闲端口；`foreground` 与 `start` 生效 |
| `-WorkerMode` | `real` | `real`（`claude -p`）或 `dummy`（测试用） |
| `-BudgetUsd` | `0.50` | 每个真实 worker 的 `--max-budget-usd` |
| `-WorkerTimeoutSeconds` | `600` | worker 进程超时回收 |
| `-WatchdogSeconds` | `30` | 看护线程刷新 heartbeat 的间隔 |
| `-AckTimeoutSeconds` | `120` | ACK 超时（首次超时重投一次） |
| `-LostSeconds` | `120` | 无心跳判定失联 |

- daemon 监听 `127.0.0.1`，端口写入 `.claude/orchestrator/daemon.json`。
- 停止会回收全部 worker。
- token：`.claude/orchestrator/token`（**不要提交、不要外传**）。
- `-Action start` 是 detached 模式；长期调试仍建议 `foreground`。

### 3.5 中控终端视图（foreground）

`-Action foreground`（或直接 `uv run python -m tools.orchestrator.service --serve`）会在终端打印启动横幅与已注册 agent 表：

```text
AgentSentinel 编排中控已启动
  pid:         27440
  listen:      127.0.0.1:14856
  home:        ...\.claude\orchestrator
  worker mode: real
  started at:  2026-11-09T00:55:48Z

role       pid      status       alive  last_heartbeat             current_task_id
doc        22772    registered   在线   2026-11-09T00:55:55Z       -
```

- 表列：`role` / `pid`（进程编号）/ `status` / `alive`（在线/已停止）/ `last_heartbeat` / `current_task_id`。
- 无注册时显示 `暂无已注册 agent`，不会留下空白终端。
- 不带 `--watch` 时默认不周期刷新，只打印启动快照（`671e2c0` 已交付并认单）；双击 `.cmd` 已默认带 `-Watch`（`7a484ed`）。需要周期刷新时显式设置 `PRISM_ORCH_DASHBOARD_REFRESH_SECONDS=<正数秒>`（旧名 `SENTINEL_ORCH_DASHBOARD_REFRESH_SECONDS` 读取兜底），设为 `0` 同为只打印快照。
- 手动查看当前快照：`uv run python -m tools.orchestrator status`（或 MCP `orchestrator_status`）。
- 事件驱动刷新（阶段 B，`918aca6` 已交付，本地未 push，已认单）：`-Action foreground -Watch` 或 `--serve --watch`；注册/停止/任务状态变化时重绘，空闲不输出；仅 `last_heartbeat` 变化默认不重绘，加 `--show-heartbeat` 才重绘。
- `GET /events`（SSE，Bearer token）：先下发 `event: snapshot`，之后状态变更下发 `id: <revision>` + `event: snapshot|heartbeat|shutdown`；每 20s 发 `: ping`；慢客户端只保留最新快照。浏览器原生 `EventSource` 不能携带 `Authorization` 头，前端需用 `fetch()` + `ReadableStream`。
- `GET /logs/stream?tail=100[&role=<role>]`（SSE，Bearer token）：回放 `logs/*.log` 最后 `tail` 行（默认 200、上限 1000）并持续跟随新增行；`event: log` + `data: {"role","line","ts"}`；不传 `role` 时推送全部日志并在约 2s 内纳入新角色日志；每 20s 发 `: ping`；daemon 停止时发 `event: shutdown`。仅覆盖 orchestrator daemon/worker 日志，外部会话终端输出需会话侧上报（`9344d33`）。
- `POST /logs/report`（Bearer token）：入参 `{role,line}`，role 白名单、空白折叠、单行 ≤4000；追加到 `logs/<role>.log`，供 `/logs/stream` 跟随。Stop Hook 在会话带 `PRISM_ROLE`（旧名 `SENTINEL_ROLE` 兜底）时上报每轮最后一条助手消息（`[turn]`，≤1200 字），只使用 Stop 事件自带的 `last_assistant_message`，不读取项目外 transcript；daemon 离线静默，Hook 需重启会话加载（`d481a93`、`2bb03c6`）。
- `POST /discover`（Bearer token）：重新探测已登记 agent 的进程存活并修正 status，恢复/清理角色缓存，扫描项目内未注册进程；返回 `{discovered, recovered, pruned, pending_registered, pending_pruned, agents, wild}`；前端「检测 Agent」按钮调用（`4d1713f`、`4cb2cbc`）。`wild` 字段为 `pid/ppid/cwd/cmdline/create_time/source/root/child_pids/bound_role`，只读、按 cwd 过滤、cmdline 截断+掩码；P2 绑定未实现。
- 项目隔离：daemon 由 home 推导 `project`（`PRISM_PROJECT_ROOT` 可覆盖，旧名 `SENTINEL_PROJECT_ROOT` 兜底）；`/register` 携带不同 project 返回 409；`/status` 的 daemon 与 agent 均含 project。MCP server 带 `PRISM_ROLE`（旧名 `SENTINEL_ROLE` 兜底）时启动即注册，并每 15s 重注册（`PRISM_ORCH_HEARTBEAT_SECONDS` 可调），daemon 重启后可再识别（`4d1713f`）。`/stop` 仅对 `job_id` 非空的 daemon 托管 worker 生效，外部 Agent 返回 409 `external_agent`（`ffed730`）。
- 角色缓存：MCP 注册成功后按 `CLAUDE_CODE_SESSION_ID` 写 `<home>/agents/<session>.json`；启动无 `PRISM_ROLE`（旧名 `SENTINEL_ROLE` 兜底）时回退缓存角色并继续心跳。daemon 每 30s（`PRISM_ORCH_AGENT_CACHE_SECONDS`）恢复存活缓存、删除死缓存；`/discover` 返回 recovered/pruned（`7aa7a80`）。窗口重置后 session id 变化，需按唤醒流程重新注册一次。
- detached 模式（`-Action start`）不输出中控视图，只写日志。
- 启动失败（端口占用等）打印可读错误并以 exit 1 结束。

## 4. 会话加载 MCP 与无感注册

项目级 `.mcp.json` 已注册 `prism` server：

```json
{"mcpServers":{"prism":{"command":"uv","args":["run","python","tools/orchestrator/mcp_server.py"]}}}
```

- **新会话启动后**才会出现 `mcp__prism__orchestrator_*` 工具；已有会话需要重启。
- doc / dev 提示词要求：会话启动时若 MCP 工具可用，静默调用一次 `orchestrator_register`；daemon 离线时不向用户报错，结果返回 `pending`，并写入会话缓存/PID File，由 15s 心跳后台重试（`114f27a`）。
- `orchestrator_register(role, session?, ref?)`：MCP server 用自身 `os.getpid()` 作为 `pid`/`pgid` 调 `/register`，`command` 记为 `mcp_server session=<...> ref=<...>`；重复调用幂等更新。daemon 离线/5xx 时结果 `pending` 并后台重试；4xx 仍按失败返回、不重试。

验证注册：

```text
orchestrator_status
orchestrator_resolve(role="dev")
```

或：

```bash
uv run python -m tools.orchestrator status
uv run python -m tools.orchestrator resolve --role dev
```

> 注意：当前是「任务即进程」。`register` 登记的是**当前会话的 MCP server 进程**，是「谁在线」的标记；真正 `need` 时会新起一个 `claude -p` worker，并把该 role 的注册记录覆盖为 worker 的 pid。**已注册的交互窗口目前不是任务执行者。**

## 5. 两种用法

### 5.1 MCP（doc 首选；doc 无 Bash）

重启会话后可用：

| 工具 | 用途 |
|---|---|
| `orchestrator_status` | daemon 与 agents 状态 |
| `orchestrator_resolve` | 查某 role |
| `orchestrator_register` | 注册当前 MCP server 为角色：`role`（必填）/ `session` / `ref`；`pid`/`pgid` 为 MCP server 自身，幂等；daemon 离线/5xx 返回 `pending` 并后台重试，4xx 按失败返回 |
| `orchestrator_need` | 派单：`from_role/to_role/intent/pointer/acceptance/budget/idempotency_key` |
| `orchestrator_ack` | 接单：`task_id/role/attempts` |
| `orchestrator_completed` | 完成：`task_id/role/artifacts/cost_tokens` |
| `orchestrator_heartbeat` | 心跳 |
| `orchestrator_task` / `orchestrator_tasks` | 任务详情 / 列表 |

派单示例：

```json
orchestrator_need(
  from_role="doc", to_role="dev", intent="implement",
  pointer="docs/local/交流区/交流区.md#P-12",
  acceptance=["测试通过", "STATUS 已更新"],
  idempotency_key="P-12:dev:v1",
  budget={"max_tokens": 200000, "max_minutes": 30}
)
```

### 5.2 CLI（dev / 人工调试）

```bash
# 派单
uv run python -m tools.orchestrator need \
  --from-role doc --to-role dev --intent implement \
  --pointer "docs/local/交流区/交流区.md#P-12" \
  --acceptance "tests pass" --idempotency-key P-12:dev:v1

# 接单 / 完成
uv run python -m tools.orchestrator ack --task-id <TID> --role dev --attempts 1
uv run python -m tools.orchestrator completed --task-id <TID> --role dev \
  --artifact workspace/out --cost-tokens 0

# 查询
uv run python -m tools.orchestrator status
uv run python -m tools.orchestrator tasks
uv run python -m tools.orchestrator task --task-id <TID>

# 仅测试用 dummy worker
uv run python -m tools.orchestrator start --role dev --dummy
uv run python -m tools.orchestrator stop --role dev
```

## 6. 一次派单发生了什么

```text
doc: orchestrator_need
  → daemon 建 task（queued）
  → 停掉目标 role 现有 worker，新起一个 claude -p worker
    （角色提示 + pointer + acceptance + attempts + ORCHESTRATOR_*）
  → worker 先 ack（带 attempts）→ 任务 running
  → worker 执行、写产物
  → worker completed（artifacts）→ 任务 done
  → daemon 关闭该 worker 的 Job，回收进程
```

- 无 ACK：120 秒 → 重投 1 次 → 再超时 `timeout`。
- 心跳 30 秒；失联 120 秒 → `failed(heartbeat_lost)`。
- 旧 attempt 的迟到 ACK 返回 409。
- 重复 `idempotency_key` 返回既有 task，不重复起进程。
- token 预算是**事后判定**（worker 退出时才解析 usage）；实时约束是 `--max-budget-usd` 与分钟上限。

## 9. 安全边界

- 仅监听 `127.0.0.1`；除 `/health` 外均需 Bearer token。
- 不读项目外路径；`.claude/orchestrator/` 不入库。
- 真实 worker 工具：`Read / Glob / Grep / Edit / Write / Bash` + 编排 MCP；权限 `manual` + `--permission-prompts none`，不自动放行。
- dummy 不继承模型凭证；只有 `spawn_real` 注入 `ANTHROPIC_*` / `CLAUDE_CONFIG_DIR` / Git Bash。
- `/register` 不做身份鉴权（沿用 P1 口径）。
- 不自动 push、不绕过用户权限。
- **不接入产品**：`agentsentinel/**` 不引用编排服务。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| `daemon not running` / MCP 返回 503 | 在外部终端启动 daemon；不要在 agent Bash 里常驻 |
| `401 unauthorized` | token 不一致；重启 daemon 或读 `.claude/orchestrator/token` |
| `409 role busy` | 该角色已有活动任务；等完成或 `stop --role` |
| `timeout` / `heartbeat_lost` | 看 `logs/` 与 `task --task-id`，检查 worker 是否退出 |
| MCP 工具不存在 | 重启会话加载 `.mcp.json` |
| foreground 终端没有输出 | 应显示中控横幅与 agent 表；确认不是 `--no-dashboard` / detached 模式；升级到 `7071c6c` 后可用 |

## 1. 启动与数据源

```text
双击 start_frontend.bat
  → VBS 隐藏启动 → tauri dev
  → App 挂载
      ensureDaemon()：读 <root>/.claude/orchestrator/daemon.json
        ├─ /health 正常 → 复用现有 daemon
        └─ 否则用项目 home 执行 uv run python -m tools.orchestrator.service --serve --port 8765
      → GET /status + GET /tasks
      → 打开 GET /events（状态 SSE）
      → 打开 GET /logs/stream?tail=100（日志 SSE）
```

- daemon 地址每次请求前读 `daemon.json`，端口变化可跟随；读不到时回退 `127.0.0.1:8765`（`src/lib/backend.ts:37-49`）。
- token 从 `<root>/.claude/orchestrator/token` 读入 JS 内存，所有 Bearer 请求自动携带（`backend.ts:101-108,175-179`）。
- 启动超时 20s；React StrictMode 双挂载通过模块级 in-flight Promise 去重（`backend.ts:60-87`）。
- 关闭窗口时 abort 两条 SSE、取消任务重取定时器，并尝试结束由本应用拉起的 daemon（`App.tsx:178-185`）。

| 数据源 | 用途 | 触发方式 |
|---|---|---|
| `GET /status` | daemon + agents 快照 | 启动、命令面板「刷新」、停止失败后回滚 |
| `GET /tasks` | 任务列表 | 启动、SSE snapshot 后去抖重取、停止后 |
| `GET /events` | 状态 SSE：`snapshot` / `heartbeat` / `shutdown` | 启动后常驻，断线退避重连 |
| `GET /logs/stream?tail=100` | 后端日志 SSE：回放 100 行后跟随 | 启动后常驻，断线退避重连 |
| `POST /discover` | 重探存活 + 恢复/清理缓存 + 未注册进程 | 仅「检测 Agent」按钮 |
| `POST /stop` | 停止 daemon 托管 worker | 仅托管 Agent 的「停止」按钮 |

## 10. 数据刷新与重连

- **无轮询**：不使用 `setInterval` / `EventSource`；状态与日志均为 SSE（`sse.ts` 文档注释、源码静态检查要求）。
- `/events`：
  - `snapshot`：更新 daemon + agents，并去抖 250ms 重取 `/tasks`；
  - `heartbeat`：更新 daemon + agents，**不**重取 `/tasks`；
  - `shutdown`：标记连接关闭；
  - 断线后指数退避重连（1s 起、上限 15s、±20% 抖动），每次重连重新解析 `daemon.json`（`App.tsx:74-110`、`sse.ts:55-64,95-142`）。
- `/logs/stream`：
  - 连接时回放最后 100 行，随后跟随新增行；`[role]` 前缀并入 Console；
  - 与状态流独立重连；后端 `event: shutdown` 不写入 Console；
  - 每次重连会再次回放 100 行（当前无跨连接去重）。
- **检测 Agent** 是唯一更新 `wild`（未注册进程）的入口。
- 命令面板「刷新」只重取 `/status` + `/tasks`；「重新连接 SSE」重启两条流。

## 11. 产品边界

- **中控不杀外部进程**：`/stop` 仅对 `job_id` 非空的 daemon 托管 worker 生效；外部 Agent 返回 409 `external_agent`，不改状态、不杀进程（`tools/orchestrator/service.py:718-741`）。
- 前端：外部 Agent 显示「外部进程」，不提供停止按钮（`AgentTable.tsx:43,70-88`）。
- 不杀 MCP server、不注入、不新增退出协议；外部窗口由用户自行 Ctrl+C/关闭。
- 暂无 UI 启动托管 worker 的入口；托管 worker 仍由 daemon/CLI 创建。
- 未注册进程只读展示；P2 手动绑定未实现。
