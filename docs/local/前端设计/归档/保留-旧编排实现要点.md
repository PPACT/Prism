## 1. 运行时上下文治理（已实现 `ae90372` + P1 修正 `36f3d92`）

### 1.1 阈值与动作

| 条件 | 动作 |
|---|---|
| `ratio < 0.55` | `OK`，不写盘 |
| `0.55 <= ratio < 0.90` | 原生压缩生成摘要 → 写 `context-summary/<role>.json` → `SOFT_SUMMARIZED` |
| `ratio >= 0.90` | **先**原生压缩并**重新测量**：仍 ≥0.90 → 写 checkpoint → 进程内 reset → `HARD_RESTARTED`；已低于 0.90 → 写摘要 → `HARD_COMPRESSED` |
| 压缩抛错 | 先写 checkpoint（`pending_action=context_compression_failed`）再 reset；禁止静默继续 |

**硬红线**：绝不直接清空上下文；必须先压缩、复测，仍超限才 checkpoint + reset。

### 1.2 契约（`agentsentinel/contracts.py`）

- `Checkpoint`：`schema_version` / `role` / `status: SessionState` / `artifacts`（工作区相对路径）/ `pending_action` / `audit_cursor` / `context_summary_path` / `created_at`。
- `ContextSummary`：`role` / `generated_at` / `used_tokens` / `context_window` / `ratio` / `summary` / `pending_action` / `strategy`（`native` 或 `deterministic`）。
- `SessionState` 已迁入 `contracts.py`；`roles/orchestrator.py` 重新导出，保持既有导入路径不破。
- `audit_cursor` 口径：`<ISO-8601>#<sha256[:12]>`（时间 + 记录哈希），不用行号。

### 1.3 配置与存储

```text
SENTINEL_CONTEXT_MONITOR_ENABLED=true
SENTINEL_CONTEXT_SOFT_RATIO=0.55
SENTINEL_CONTEXT_HARD_RATIO=0.90
```

校验：`soft < hard <= 0.9`（AgentScope `trigger_ratio` 上限 0.9）。不新增 `context_window` 配置，分母取 `agent.model.context_size`。

存储（gitignored，工作区相对路径）：

```text
workspace/reports/checkpoints/<role>.json          # 每角色仅保留最新一份
workspace/reports/context-summary/<role>.json      # 按角色分文件，防并发覆盖
```

### 1.4 水位计数与 reset 语义

- 计数必须用 `agent._prepare_model_input()` 取实际发送的 `messages` / `tools`，再 `model.count_tokens(...)`；**不得只数 `state.context`**（会漏掉 `state.summary`、system prompt 与工具 schema，P1 事故）。
- reset：清空 `state.context`；`state.summary = build_resume_text(...)`；保留 `permission_context` / `tool_context` / `tasks_context`；重置 `reply_context`；不重读项目文件。
- 恢复文本 ≤40 行：`role/status`、`pending_action`、`artifacts` 路径、`audit_cursor`、摘要正文。

### 1.5 验收要点（保留测试语义）

- <55% 不写盘；55–90% 写摘要；≥90% 压缩后仍高 → checkpoint + restart 一次；压缩失败 → checkpoint 后 reset。
- `state.context` 为空但 `state.summary` 很大时，水位必须反映总量。
- 显式传入工具 schema 时必须计入。
- 无 checkpoint 重启 → `CheckpointNotFound`，不静默新建。
- 多角色 checkpoint / summary 文件互不覆盖；`stub` 后端不联网。

### 1.6 已裁决

阈值 0.55 / 0.90；`SessionState` 用枚举并迁入 contracts；按角色分文件存摘要；中控 API 仅监听 `127.0.0.1`、MVP 不做密钥鉴权。中控 UI 与刷新方式（轮询/SSE）仍未定。

## 2. 异构模型调度（P2-3，已实现 `5489f05`）

### 2.1 原则

- **供应商无关**：统一走 OpenAI Chat Completions 兼容协议（`OpenAIChatModel` + `OpenAICredential`），`base_url` + `model` 决定供应商；不写死供应商类或模型 ID。
- **不新增依赖**：复用 `agentscope[full]` 内置实现。
- 只有两档：`premium` / `economy`；Key 在 `.env.example` 留空。

### 2.2 角色 → 档位

| 角色 | 档位 |
|---|---|
| Orchestrator | economy |
| Writer | economy |
| Coder | premium |
| Tester | premium |
| Manager | 不接模型 |

### 2.3 环境变量

```text
SENTINEL_MODEL_BACKEND=stub|real

SENTINEL_PREMIUM_BASE_URL=
SENTINEL_PREMIUM_MODEL=
SENTINEL_PREMIUM_API_KEY=
SENTINEL_PREMIUM_TEMPERATURE=0.0
SENTINEL_PREMIUM_MAX_TOKENS=8192

SENTINEL_ECONOMY_BASE_URL=
SENTINEL_ECONOMY_MODEL=
SENTINEL_ECONOMY_API_KEY=
SENTINEL_ECONOMY_TEMPERATURE=0.2
SENTINEL_ECONOMY_MAX_TOKENS=4096
```

规则：`stub` 不读取模型配置、零网络；`real` 下 `model` 与 `api_key` 非空（空串/纯空白视为缺失），缺失时抛 `RuntimeError` 并列出缺失变量名；`base_url` 可空（走 OpenAI 默认端点）；`SecretStr` 防泄露；不新增 `SENTINEL_OPENAI_API_KEY` 路由语义（legacy 兼容）。

### 2.4 模型驱动与工具边界

- 接线优先级：显式 `model_factory` > `model_backend="real"` 的 `ModelRouter` > 默认 scripted model；`None` 时专家角色保持确定性 `handle()`。
- 真实模式不得把 AgentScope 内置 `Bash` / `Write` / `Edit` 直接交给专家角色；使用工作区受限工具：
  - Coder：`file_read` / `file_write` / `file_edit`，限 `workspace/code/`。
  - Tester：`file_read` 限 `workspace/` + `submit_test_report` 写 `workspace/reports/`。
  - Writer：`file_read` 限 `workspace/` + `file_write` / `file_edit` 限 `workspace/docs/`。
- 越界路径由 `Workspace._resolve` 拒绝；Tester 首期无 shell；未提交报告判 `FAIL`；Coder 未写文件判失败；异常向上抛，由编排写状态流。

### 2.5 冒烟与已知风险

- `scripts/smoke_model_router.py`：读取两档配置、打印 `base_url` / `model`、发一次最小请求；缺配置非零退出；真实 Key 不入库。
- 真实端点冒烟已通过（2026-11-05，DeepSeek `deepseek-flash`，响应 `ok`）。
- 已知风险：`run_agent_sync` 在已有事件循环时用独立线程新循环；按档缓存的 `OpenAIChatModel` 跨 loop 复用 client 存在风险，真实端点需重点验证。

## 3. 用量与预算（P2-3c，已实现 `b3c6857`）

### 3.1 口径

| 项 | 口径 |
|---|---|
| 统计范围 | 单次 `pipeline.run()` 进程内累计；`usage.jsonl` 保留全量 |
| 独立日志 | `workspace/reports/usage.jsonl`，不混入 `push-log.jsonl` / `pipeline-state.jsonl` |
| 成本公式 | `input/1e6*input_price + output/1e6*output_price`；货币单位自定，代码不换算 |
| 缓存 Token | `cache_input_tokens` / `cache_creation_input_tokens` 只记录、不折价（MVP） |
| 缺用量 | 记零值并标 `usage_available=false`，不静默丢账 |
| 重试 | 每次重试独立计量 |

### 3.2 环境变量

```text
SENTINEL_BUDGET_LIMIT=0
SENTINEL_PREMIUM_INPUT_PRICE_PER_MTOK=0
SENTINEL_PREMIUM_OUTPUT_PRICE_PER_MTOK=0
SENTINEL_ECONOMY_INPUT_PRICE_PER_MTOK=0
SENTINEL_ECONOMY_OUTPUT_PRICE_PER_MTOK=0
```

- 全部 `>=0`；`budget_limit=0` 表示不启用。
- **fail-closed**：预算已启用但对应档位两项单价均为 0 → 调用前抛 `RuntimeError`，消息只列变量名、不回显 Key。

### 3.3 实现要点

- `UsageLedger`：线程安全累计 + 追加 JSONL；`check()` 调用前判超限，超限写 `exceeded=true` 并抛 `BudgetExceededError`。
- `MeteredChatModel`：包装真实模型，`_call_api` 前 `check`、返回后 `record`；委托 `_get_retryable_exceptions`；`stream=True` 直接报错，避免静默漏记。
- `UsageRecord` 字段：`timestamp` / `run_id` / `role` / `tier` / `model` / `input_tokens` / `output_tokens` / `cache_input_tokens` / `cache_creation_input_tokens` / `estimated_cost` / `cumulative_cost` / `budget_limit` / `exceeded` / `usage_available`。
- 流水线捕获 `BudgetExceededError` → `FAILED`（`预算熔断：<原因>`），不写 push-log、不重试、不推送；CLI 退出码 1。
- Fast Path 不调用模型，不产生用量记录；直接使用 `ModelRouter` 的外部调用方不自动计量（计量是流水线职责）。

### 3.4 已知上限

- 供应商不返回 `usage` 时成本按 0 计，该端点无法被预算约束（用 `usage_available=false` 明示）。
- 在途调用最多超支一次（调用前检查、返回后累计）。
- 缓存 Token 不折价，估算成本可能高于实际账单。
- 单次运行口径不限制跨 run 累计花费。
- 专家角色工具内触发的超限异常会被 AgentScope Toolkit 吞成 `tool_result` ERROR；熔断在主编排下一次模型调用时生效（仍 fail-closed）。

## 5. 重构注意事项

1. 新方案只替代**开发期跨会话互通**；上述产品运行时治理、模型路由、用量预算代码仍有效，除非用户另行决定重构。
2. 保留既有红线：不新增依赖（须按 `AGENTS.md` §2 申请）、不读项目外路径、密钥用 `SecretStr` 且不入日志、预算 fail-closed、绝不静默成功。
3. 若改动 `Checkpoint` / `ContextSummary` / `UsageRecord` 字段，需同步 `contracts.py`、状态流与测试；不要恢复已删除的共享角色文件方案。
4. 上下文阈值 0.55 / 0.90 与 AgentScope `trigger_ratio` 上限绑定；改阈值前先核对 `agentscope` 版本。
5. 模型供应商保持无关；不要重新引入供应商专用类或写死模型 ID。
