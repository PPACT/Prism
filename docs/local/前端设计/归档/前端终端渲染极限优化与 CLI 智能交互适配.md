# 工单：前端终端渲染极限优化与 CLI 智能交互适配

## 1. 背景与核心目标
当前工作台的内嵌终端存在渲染错位、卡顿以及高 CPU 占用问题。我们必须坚持产品底线：
1. **绝不阉割厂商能力**：必须保留厂商 CLI 100% 原汁原味的能力（包括复杂菜单、`y/n` 确认等）。
2. **极致轻量与丝滑**：前端不能成为“电老虎”，日常办公必须在【对话】页完成，且绝不能有卡顿感。
3. **一致性基准**：保留【原生终端】作为验证前后端数据是否一致的最高基准。

## 2. 核心重构方案

### 方案 A：渲染极限压榨（性能优化）
*   **强制 GPU 加速**：必须为 `xterm.js` 开启 **WebGL 渲染器**，绝对不要用默认的 DOM 渲染，把画字开销转给显卡。
*   **高频数据批处理（Batching）**：前端接收 SSE 数据流时，不要每来一个字符就调一次 `term.write()`。引入“数据缓冲区”，按 16ms~30ms 的间隔（或积攒到一定字节量），合并一次性写入终端。
*   **按需渲染（懒加载/挂起）**：当用户停留在【对话】页时，隐藏的【原生终端】必须暂停渲染动作（只接收数据存入内存，不调用 xterm 的绘制方法）；切回【原生终端】Tab 的瞬间，再将堆积的数据瞬间刷出并恢复渲染。

### 方案 B：精准尺寸同步（解决画面缺失与错位）
*   **Resize 强同步**：前端必须用 `ResizeObserver` 精确监听终端容器的尺寸变化。
*   **隐藏状态处理**：当终端在后台被隐藏（`display: none`）时，`xterm.js` 无法正确计算 `cols` 和 `rows`。因此，在用户切回【原生终端】的瞬间，必须立刻调用 `FitAddon.fit()` 重新计算尺寸，并将最新的行列数同步给后端 PTY，确保前后端的网格严格 1:1 对齐，彻底解决 TUI 菜单错位问题。

### 方案 C：对话界面的智能交互适配（无需切屏完成 CLI 交互）
*   **语义拦截**：中控后台实时读取 PTY 输出流。当正则匹配到 CLI 正在等待用户输入（如 `(y/n)`、`[Enter]`、`Press any key` 或选项列表）时，向当前前端推送一个 `action_required` 特殊事件。
*   **气泡联动**：前端在【对话】界面的最新气泡下方，渲染出对应的可点击按钮（如【确认】、【取消】）。
*   **指令注入**：用户点击按钮后，前端发送指令给中控，中控直接模拟键盘向底层 PTY 的 `stdin` 写入对应字符（如 `y\r`），实现“在对话页直接完成 CLI 操作”。

## 3. 验收标准
1. **资源消耗**：停留在【对话】页时，任务管理器中 WebView 的 CPU 占用率应极低；打字无延迟。
2. **渲染精度**：切到【原生终端】，CLI 的边框、菜单、光标位置必须完全对齐，无任何截断或错位。
3. **交互闭环**：当底层 Agent 触发需要权限确认的操作时，【对话】页能直接弹出确认按钮，点击后命令能成功执行，无需切屏。
