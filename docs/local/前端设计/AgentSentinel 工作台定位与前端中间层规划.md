# AgentSentinel 项目架构定位与前端中间层规划

> **文档目的**：明确项目的核心定位、架构边界，并为下一步的“前端图形化工作台”开发定下基调。
> **适用对象**：doc-agent、dev-agent。

## 一、 项目核心定位（我们到底在做什么？）

1.  **不是自研 Agent 底层引擎**：我们不重造大模型 API 的轮子，不自己写工具执行器。厂商在 CLI（如 `claude`）层面做的上下文管理、沙箱权限、工具调用已经足够优秀，我们直接白嫖。
2.  **不替代现有 CLI 的工作流**：大部分高级用户和开发者依然喜欢用 `CLI + API` 的模式。我们的产品**完美兼容**这种模式。
3.  **我们做的是“人类友好的中间层外壳”**：CLI 对 LLM 极度友好，但对人类极度不友好（黑框、刷屏、排版差）。我们要做的是在 CLI 之上，套一个**自带中控调度 + 图形化界面的“高级工作台”**。

**架构比喻（数据流向）**：
`LLM 模型` ➡️ `厂商 CLI 引擎 (claude)` ➡️ `中控 Daemon (数据总线/进程管理)` ➡️ `Tauri 前端 (人类可视化)`

## 二、 技术实现路线

### 1. 底层执行：无头 CLI (`claude -p`)
*   中控 Daemon 在拉起 Worker 进行任务或对话时，依然调用原生的 `claude` CLI。
*   为了配合前端，Daemon 在启动 CLI 时，强制加上 `--output-format stream-json` 参数，将原本黑框里的纯文本变成结构化的 JSON 数据流。
*   通过 `--session-id` 维持多轮对话的记忆，保证每一轮交互都能接续之前的上下文。

### 2. 通信层：Daemon 解析与分发
*   Daemon 监听 CLI 的 `stdout` 输出，按行读取 JSON 流。
*   Daemon 保留现有的 `POST /chat` 接口接收前端输入，并通过现有的 SSE 接口，把解析好的 JSON 流实时推送给前端。
*   **生命周期极其严格**：前端发起的对话，由 Daemon 拉起进程。一旦前端关闭对话窗口，Daemon 必须通过 Job Object 机制将该 CLI 进程瞬间秒杀，绝不留下后台幽灵进程。

### 3. 表现层：前端的“富文本渲染”（脱离 xterm）
*   **拒绝纯字符终端**：前端不引入 xterm.js。我们要用现代前端框架渲染。
*   **块级解析（Content Blocks）**：前端拿到 JSON 后，不能按顶层分类，必须解析内部嵌套的 `message.content[]`，将数据映射成不同的 UI 组件：
    *   `thinking`：渲染为灰色的、默认折叠的“思考面板”。
    *   `text`：渲染为支持 Markdown 的正式回复（高亮代码、换行等）。
    *   `tool_use`：渲染为带有图标的状态条（例如：`[⚙️ 正在读取 xxx.py]`）。
    *   `tool_result`：渲染为结果反馈卡片。

## 三、 核心功能模块拆解

### 1. 交互面板（类 Cursor Chat）
*   底部固定输入框，支持 `Enter` 发送、`Shift+Enter` 换行。
*   上方为滚动消息列表，用户的提问与 Agent 的回复以卡片形式排列。
*   所有流式输出（Streaming）必须以 60fps 丝滑渲染。

### 2. 开发日志流水（自动脱敏）
*   在两轮对话结束后（Daemon 收到流结束标志），自动提取用户的提问和 Agent 的最终文本。
*   经过 `RegexSanitizer`（敏感信息脱敏）后，追加记录到 `docs/local/开发日志.md`。
*   前端侧边栏提供一个“开发日志”面板，实时渲染这本流水账。

### 3. 中控监控面板（现有功能保留）
*   原本的 Agent 列表、任务列表、底层 Console 日志全部保留，作为“上帝视角”供排查问题。

## 四、 实施步骤建议（PoC 先行）

请 dev-agent 按以下步骤执行：

*   **Step 1（验证底层数据流）**：不用写任何前端 UI。先写一个命令行脚本，调用 `claude -p --output-format stream-json`，抓取真实的 JSON 输出样本，验证通过 `--session-id` 进行多轮对话的可行性。
*   **Step 2（Daemon 改造）**：在 Daemon 中实现 `POST /chat` 接口，通过 SSE 推送解析后的流数据。确保 CLI 进程挂载在 Job Object 下。
*   **Step 3（前端解析器）**：前端实现 JSON 解析逻辑，做好“折叠思考/显示文本”的映射。
*   **Step 4（UI 联调）**：把输入框和消息流加上，完成端到端闭环。
*   **Step 5（日志落盘）**：加入脱敏逻辑和日志写入。

## 五、 产品边界与风险确认

1.  **打破旧红线**：允许中控拉起并托管专用于聊天的 CLI 进程。
2.  **不杀外部进程**：用户自己手动用黑框开着的 CLI，中控依然只观察不干预。
3.  **防堆积兜底**：前端关闭、中控退出，必须保证交互进程 100% 被回收。
