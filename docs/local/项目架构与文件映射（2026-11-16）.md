# AgentSentinel 项目架构与文件映射（2026-11-16）

> 用途：大重构前的全项目拆解。回答两个问题：① 这个仓库到底由哪几个系统组成；② 每个文件负责什么。
> 依据：当前源码（`main = 654e472` 已 push，工作区另有未提交改动）+ `docs/local/` 现行文档 + 2026-11-15/16 交接记录。
> 原则：源码优先；无法从源码确认的标「待确认」。本文只读源码后整理，**未改任何代码**。
> 位置：`docs/local/`，不进 git。
> 更新（2026-11-16）：Prism 第一步已完成（未提交）——工作台品牌、`PRISM_*` 环境变量、MCP 名 `prism`、数据目录 `%APPDATA%\Prism` 已落地；本文已按源码同步，旧名仅在兼容兜底处保留。

## 0. 三句话结论

1. 仓库里实际有 **3 个可独立演进的子系统**：产品流水线 `agentsentinel/`、开发期编排服务 `tools/orchestrator/`、桌面工作台 `experiments/frontend-dashboard-tauri/`；现有文档常把三者混称「编排」。
2. 有 **三组同名不同物** 必须先改名，否则重构必乱：`Orchestrator`（产品角色 vs 开发编排服务）、`Workspace`（产物目录 vs 用户项目配置）、`Agent`（产品角色 vs 注册到 daemon 的 Claude 会话）。
3. 主要耦合集中在两个巨型文件：`tools/orchestrator/service.py`（4,376 行）与 `src/lib/backend.ts`（682 行）；前端另有 `App.tsx`（1,306 行）承担了过多编排职责。

## 1. 架构总览（重构视角）

### 1.1 三个子系统

| 子系统 | 目录 | 运行形态 | 是否产品 | 依赖方向 |
|---|---|---|---|---|
| 产品流水线 | `agentsentinel/` | `python -m agentsentinel run --stub`（离线）或真实模型 | **是** | 只依赖自身 + AgentScope |
| 开发期编排服务（Prism 工作台后端） | `tools/orchestrator/` | 常驻 daemon + 每会话 MCP server + `claude -p` worker | 否（开发工具） | 不依赖产品包（2026-11-16 已删除唯一反向依赖 `chat.py`） |
| 桌面工作台 | `experiments/frontend-dashboard-tauri/` | Tauri 窗口 + React 前端 + 本地 daemon/PTY | 实验/工作台 | 只通过 HTTP/SSE 访问 daemon |

补充：`.claude/hooks/` 是**开发期兜底治理**，不参与上述三者运行；`scripts/` 是启动/清理/演示等运维脚本。

### 1.2 进程与数据流

```text
启动工作台.vbs / .bat
  └─ scripts/launch_workbench.py (pythonw, 无黑框)
       ├─ 拉起 daemon: python -m tools.orchestrator daemon start
       │    └─ terminal_pool 开启时: 每个 Agent/Shell 一个 ConPTY → claude / PowerShell
       └─ 拉起 Tauri 窗口 (npm run tauri dev / vite)

Claude 会话
  └─ .mcp.json → uv run python tools/orchestrator/mcp_server.py
       └─ HTTP + Bearer token → daemon (127.0.0.1)
            ├─ Registry (agents)
            ├─ Router / TaskStore (tasks/messages/steps/effects/usage)
            ├─ Launcher (claude -p worker + Windows Job Object)
            ├─ TerminalManager (PtyManager 池 / 单 PTY 兼容)
            ├─ WorkspaceStore (workspaces.sqlite3)
            └─ SSE /events, /logs/stream；PTY SSE /pty/<id>/stream

前端 (React)
  ├─ /status /tasks /events /logs/stream
  ├─ /pty/terminals, /pty/<id>/{start,input,resize,stop,stream,chat/stream}
  └─ /workspaces/*, /discover, /wild/cleanup, /handoff
```

### 1.3 分层

| 层 | 内容 |
|---|---|
| 产品能力层 | 五角色 Supervisor 流水线、治理（脱敏/权限/Git）、工作区与审计、上下文治理 |
| 开发编排层 | 多 Claude 会话注册、任务派发/ACK、MCP 代理、worker 生命周期、PTY 池 |
| 交互层 | Tauri 壳、React 工作台、xterm 终端、对话/进度/终端三页 |
| 开发治理层 | `.claude/hooks/*`（git 守卫、路径守卫、夹具守卫、日志上报、待办投递） |
| 验证层 | `tests/`（产品 + 编排）、前端 `*.test.ts(x)`、`bench/` |

## 6. 前端当前行为基线（供重构验收）

- **布局**：顶栏 wordmark + 工作区 + SSE + Ctrl+K；左侧唯一会话坞；中间三页常驻（对话/进度/终端）；右侧任务面板可拖宽；底部 Console。
- **双形态**：默认单 PTY 三页共享；`PRISM_TERMINAL_POOL=1`（旧名 `SENTINEL_TERMINAL_POOL` 读取兜底）时每会话独立 PTY，按 `terminal_id` 路由。
- **五色状态**：报错红 > 离线灰 > 待处理黄（Hook，无上限）> 运行中蓝（任务/未完成 tool_use/3s 输出）> 在线绿（`end_turn` 立即回绿）。
- **Token**：数字向下取整；Tooltip 显示精确整数；增量读 JSONL `input+output` 差值；紫色分段预算条。
- **渲染**：xterm + WebGL 0.19（失败回退）；SSE 24ms 合批；非活动终端卸载 DOM/WebGL；`scrollback:1000`；resize 150ms 防抖且仅变化时发送。
- **权限等待**：`--settings` 注入 Hook → 对话页横幅 → 切原生终端，不自动按键。
- **身份**：daemon 侧 `identity_pid` 穿透 `uv/python` 包装链锚定宿主 `claude.exe`；前端遇到 409 `stale_agent` 静默 `/status` 自愈。
