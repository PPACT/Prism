## 0. 结论（先看三条）

1. **拆分可行**：工作台只通过 HTTP/SSE 访问 daemon，前端不 import Python；2026-11-16 已删除唯一反向依赖 `tools/orchestrator/chat.py`（原 `agentsentinel.governance.sanitizer`），两仓库无代码依赖。
2. **风险不在挪目录，而在写死的名字**：`SENTINEL_` 环境变量家族（约 40 个）、`%APPDATA%\AgentSentinel`、`.claude/orchestrator`、`agentsentinel-console` 可执行名、Tauri `identifier`、`tools.orchestrator` 模块路径、MCP server 名 `sentinel`。
3. **建议顺序**：先冻结基线 → **在原仓库内完成配置抽离/改名并跑绿** → 再物理拆目录。不要边搬边改；否则测试失败无法区分是搬家错还是改名错。**第一步已于 2026-11-16 完成并跑绿（未提交）。**

## 1. 两个仓库的边界

| 仓库 | 职责 | 运行形态 | 不包含 |
|---|---|---|---|
| **A. AgentSentinel 流水线** | 五角色 Supervisor 流水线、治理（脱敏/权限/Git）、上下文治理、Webhook、审计、用量 | `python -m agentsentinel run --stub` 或真实模型 | Tauri、PTY、进程嗅探、多会话编排 |
| **B. 工作台外壳** | Tauri 窗口 + React 前端 + 本地 daemon + 多 Agent 注册/任务派发 + PTY 池 + 进程嗅探 | Tauri app + 常驻 daemon + 每会话 MCP server | 产品流水线业务、模型路由、脱敏规则（除非裁决为共享包） |

拆分后依赖方向：

```text
B 工作台 ──HTTP/SSE──> B 自己的 daemon（同仓库，无跨仓库代码依赖）
B 工作台 ──拉起──> 用户项目里的 claude / codex / PowerShell
A 流水线 ──独立运行，不感知工作台
```

**目标状态**：工作台仓库内 `grep -i agentsentinel` 只允许出现在迁移兼容层、历史文档、示例夹具；运行时代码为 0 命中。

### 5.1 Python：单一配置模块

新增 `tools/orchestrator/app_config.py`（或 `branding.py`），所有模块从这里取值：

```python
APP_NAME = os.environ.get("WORKBENCH_APP_NAME", "Workbench")
APP_SLUG = "workbench"
DATA_DIR_NAME = os.environ.get("WORKBENCH_DATA_DIR_NAME", APP_NAME)
ENV_PREFIX = "WORKBENCH_"
LEGACY_PREFIX = "SENTINEL_"
DEFAULT_WORKSPACE_NAME = APP_NAME
RUNTIME_HOME_NAME = "orchestrator"
MCP_SERVER_NAME = "sentinel"          # 第一阶段不变

def env(suffix: str, default: str | None = None) -> str | None:
    """新前缀优先，旧前缀回退；两条都空返回 default。"""

def user_data_dir() -> Path: ...      # 新目录 → 旧目录回退
def default_home() -> Path: ...       # 配置的 runtime home

```

第一阶段只抽**名称 / 路径 / 默认值**；`os.environ.get("SENTINEL_...")` 的 40 处可逐步改为 `env("ORCH_HOME")`，不必一次改完。

由前端/启动脚本传入；Rust 端不再写 `"AgentSentinel"`。`start_daemon` 接收的 `root` 仍是工作台安装根。
